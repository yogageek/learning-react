  * App.js 是「地圖」：它決定了網址與組件之間的「對應關係」。
     * pages.js (中的 Home) 是「內容」：它決定了當網址匹配到 / 時，畫面上具體要長什麼樣子。

    讓我們用「導航系統」來比喻：

    1. App.js (導航後台/地圖)
    它不負責畫出漂亮的導覽列，它只負責邏輯判斷。
     * 如果網址是 / -> 請把 Home 組件叫出來。
     * 如果網址是 /about -> 請把 About 組件叫出來。
     * 混淆點：雖然它看起來像是在定義結構，但它其實是在定義「規則」。

    2. pages.js 中的 Home() (目前的 UI 佈局)
    目前的 Home 組件內寫了 <h1> 和 <nav>。
     * 這意味著，只有當你在首頁 (/) 時，你才會看到那個導覽列。
     * 問題就在這：如果你點了 "About" 去了 /about，App.js 就會把 Home 換成 About。因為導覽列寫在 Home
       裡面，所以一換頁，導覽列就會消失！

  ### 🚀 React Router v6 運作與修復重點

  #### 1. 核心組件與鉤子 (Hooks)
  * **`useRoutes`**: 以 JavaScript 物件陣列定義路由，取代了舊版的 `<Routes>` 標籤寫法，讓地圖更簡潔。
  * **`<Outlet />`**: 嵌套路由的關鍵！在父組件（如 `About`）中預留位置，讓子組件（如 `Services`）可以顯示在父框架內。
  * **`useLocation`**: 用來獲取當前網址資訊，常用於開發 404 頁面以顯示錯誤路徑。

  #### 2. 版本升級關鍵改動 (v5 -> v6)
  * **`Redirect` 走入歷史**：v6 已移除 `Redirect`。
      * **修復方式**：改用 `<Navigate to="..." />` 組件。
  * **嵌套路徑簡化**：子路由的 `path` 不再需要寫完整的父路徑。例如在 `about` 下的 `services`，`path` 只要寫 `"services"` 即可，系統會自動對應到 `/about/services`。
  * **萬用字元 `*`**：將 `path: "*"` 放在路由表最末端，可捕捉所有未定義的路徑，實現 404 功能。

  #### 3. 環境與安全性修復 (專案踩坑紀錄)
  * **Node.js v20+ 相容性**：舊版 `react-scripts` 不支援 OpenSSL 3.0。
      * **指令**：啟動時需設定 `NODE_OPTIONS=--openssl-legacy-provider`。
  * **JSX 與 React 作用域**：React 17 以前的版本，JSX 檔案頂部**必須**手動加上 `import React from "react"`。
  * **預檢跳過**：若專案外層目錄有干擾的 `node_modules`，需在 `.env` 加入 `SKIP_PREFLIGHT_CHECK=true`。
