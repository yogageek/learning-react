### useEffect

產生**副作用（side effect）**，可以想像成所有不是為了產生渲染結果而執行的額外工作。分成 effect 函式與清除函式（cleanup function）。

**相依陣列（dependency array）** 重點：
- 傳入相依陣列 → 把 UI 與特定狀態的變動掛勾，決定執行時機
- 傳入**空陣列** → 只在第一次渲染時執行
- 從 effect 回傳另一個函式 → 該函式會在元件 unmount 時被呼叫
- 陣列放多個值 → 任一個變動就重新觸發

總結：`useEffect` 讓你掌控元件**建構（mount）與解構（unmount）**時的副作用，也就是初始化跟元件被移除的時候。

---

### useEffect 的坑：物件與函式的相等性

要小心——物件、陣列、函式，**只有是同一個實體（記憶體位置相同）才算相等**。所以即使值看起來一樣，每次重新渲染都可能產生新實體，導致 `useEffect` 被不必要地觸發。

這個坑很容易踩。

---

### useMemo

專門用來解決上面那個坑。

計算函式的回傳結果會被暫時記住，下次呼叫時如果輸入值沒變，直接回傳暫存結果，不重新計算。

- 第一個參數：計算函式
- 第二個參數：相依陣列，變動才重新計算

---

### useCallback

和 `useMemo` 類似，差別是**暫存的是函式本身而不是值**。

JavaScript 會把每個 function 實體都視為不相等（記憶體位置不同），所以函式每次渲染都會被當成新的，進而不必要地觸發 effect。`useCallback` 就是用來保存函式實體，解決這個問題。

> **學習思路：先記住這個 Hook 是為了解決什麼問題，不要死記語法。有坑就一定有解決方法，兩個知識點連貫在一起就比較好記住跟理解。**

---

### useLayoutEffect

和 `useEffect` 差別只在觸發時機：

- `useEffect` → 渲染且瀏覽器**繪圖之後**執行
- `useLayoutEffect` → 渲染但瀏覽器**繪圖之前**執行

大部分情況用 `useEffect` 就對了。如果副作用跟瀏覽器繪圖有關（例如外觀、UI 位置），才需要 `useLayoutEffect`。

**簡單記法：`useLayoutEffect` 就是為了解決 `useEffect` 沒辦法 handle 的場景而存在的補丁。這樣想就比較好記它是幹嘛的。**

---

### Hook 使用原則

- 只能在元件或自定義 Hook 中呼叫
- **避免在條件式（if/else）或迴圈中呼叫** → 會把呼叫順序搞亂，這是 React 背後的機制決定的
- `useEffect` 第一個參數**不能傳 async 函式**，只接受標準函式。需要非同步行為要把 async function 定義在內部再呼叫

> 這邊要搞清楚：怎樣叫標準函式、怎樣叫非同步函式、直接放匿名函式可以嗎？這個要分清楚。

---

### useReducer

可以取代 `useState`，用來處理**複雜的狀態邏輯**。

- 第一個參數：reducer 函式
- 第二個參數：初始狀態

概念來自 JavaScript 的 `Array.reduce()`，讓複雜的狀態變動更容易預測與管理。**先記住它是用來處理複雜狀態的，再去理解它的機制跟 `useState` 有何不同。**

---

### memo

`React.memo` 包裝函式元件，props 沒變就不重新渲染。傳入相同 props 永遠得到相同結果。

第二個參數（可選）：自定義比對函式，回傳 `true` 代表不需要重新渲染。

用途就是：**不要沒意義地重新渲染。**

---

### 重構的時機（重要提醒）

`useMemo`、`useCallback`、`memo` 常被過度使用。**用不好反而會降低效能，所以不能亂用。**

正確做法：先訂一個有意義的目標，例如改善畫面卡頓、鎖定某個拖慢速度的函式，再針對性地用。比一開始就無所謂地亂用還要好。

### useEffect

這個函式產生**副作用（side effect）**，可以想像成所有不是為了產生渲染結果而執行的額外工作。分成 effect 函式與清除函式（cleanup function）。

再來是**相依陣列（dependency array）**的概念，可以用來和其他狀態管理 Hook 合作（例如 `useReducer`）。

重點：
- 傳入相依陣列，可以把 UI 與某些特定狀態的變動掛勾起來，用以決定正確的執行時機
- 如果傳入**空陣列**，代表只在第一次渲染時被呼叫
- 如果從 effect 函式中**回傳另一個函式**，那個函式會在元件被移除（unmount）時被呼叫
- 如果相依陣列放入多個值，只要其中一個變動就會重新觸發 effect

總結來說，`useEffect` 可以用來掌控元件**建構（mount）與解構（unmount）**時的副作用。

### 自定義 Hook

可以把多個 Hook 封裝進一個自定義 Hook 裡面，提高重用性。

### useEffect 的執行時機與相依陣列的坑

要小心**物件與函式的相等性判斷**：只有當它們是同一個實體（記憶體位置相同），才會被判斷為相等。因此，即使值看起來一樣，每次重新渲染都可能產生新的實體，導致 `useEffect` 被不必要地觸發。

### useMemo

`useMemo` 的功能：在一個計算函式中，其所回傳的結果會被暫時記住。當該函式再次被呼叫且輸入值與暫存相同時，就會直接回傳暫存結果，不重新計算。

- 第一個參數：用於計算結果的函式
- 第二個參數：相依陣列，只有在相依陣列變動時，才會重新計算

用途：解決物件與陣列每次渲染都產生新實體的問題。

---

### useCallback

`useCallback` 和 `useMemo` 類似，差別在於**暫存的是函式本身而不是值**。

JavaScript 會把每個 function 實體都視為不相等（記憶體位置不同），這樣一來，函式每次都會被觸發。要修正這個坑，就要用 `useCallback` 把函式包起來，它會保存函式的實體，就像 `useMemo` 保存值一樣。

> 學習方式建議：先記住這個 Hook 的出現是為了解決什麼問題，不要死記語法。有坑就一定有解決方法，兩個知識點連貫在一起比較好記。

---

### useLayoutEffect

`useLayoutEffect` 與 `useEffect` 類似，差別在於觸發時機：

- `useEffect`：在元件渲染**且瀏覽器繪圖之後**執行
- `useLayoutEffect`：在元件渲染**但瀏覽器繪圖之前**執行

大部分情況下，`useEffect` 是正確的選擇。但如果副作用與瀏覽器繪圖有關（例如外觀、UI 位置調整），才需要用 `useLayoutEffect`。

簡單記法：`useLayoutEffect` 是為了解決 `useEffect` 沒辦法處理的某些場景而存在的補丁。

---

### Hook 使用原則

- Hook 只應該在元件或自定義 Hook 中被呼叫
- 依照功能差異分層，是使用 Hook 的優雅作法
- Hook 會依照順序被呼叫，**避免在條件式（if/else）或迴圈結構中呼叫 Hook**，否則會把順序搞亂
- `useEffect` 第一個參數只接受標準函式，**不能傳入 async 函式**。若需要非同步行為，要把 async function 定義在 effect 函式內部再呼叫，或使用匿名函式包裝

### useReducer

`useReducer` 可以取代 `useEffect`，用來處理**複雜的狀態邏輯**。

- 第一個參數：reducer 函式
- 第二個參數：初始狀態

概念來源於 JavaScript 的 `Array.reduce()`，接受一個函式與初始值，將多個值轉換成單一結果。用來讓複雜的狀態變動更容易預測與管理。

---

### memo

`React.memo` 可以用來包裝**函式元件**，讓它在 props 沒有變動時不重新渲染。

- 傳入相同的 props，永遠得到相同的渲染結果
- 第二個參數（可選）：自定義比對函式，回傳 `true` 代表不需要重新渲染

用途：避免沒意義的重複渲染。
